# Known limitations

Honest list. Items marked **open** are not solved.

1. **Not Blender / Three.js / GLSL.** None of those toolchains is installed here, and they would add heavy dependencies to a README asset pipeline. The renderer is a custom Canvas-2D rasteriser. Consequences: painter's-algorithm depth sorting (rare mis-ordering between large overlapping solids), no true global illumination, no per-pixel shaders, no motion blur, shadows are projected hulls. **Open** if a Level-5 "film" look with real path-traced materials is wanted.
2. **Frame rate and size.** Sources are continuous-time and could render at 60 fps, but GitHub README delivery is bandwidth-bound. Assets ship at **24 fps, 1280 px wide** (native canvas size) as lossy animated WebP at quality 70 (hero 46). An earlier 20 fps, 880 px, quality 26–42 delivery showed visible block artefacts and was replaced; the cost is weight, about 61 MB in total with a 12 MB hero, so first load of the README is slow on poor connections. The hero is the heaviest asset (see the inventory for exact sizes). Total referenced weight is checked by `verify.mjs`.
3. **Animated WebP only.** GitHub does not play repository-relative `<video>` inline. WebP animates in all current browsers; very old clients would see the first frame. Reduced-motion users receive static posters via `<picture>`.
4. **Illustrative content is labelled, not hidden.** The score thresholds in the Logic Machine, the response stream volume in Information Becomes Structure, the request path in Engineering, the deviation readout in Precision and the event timing in Integrations are illustrative. Each is marked on the frame (`ILLUSTRATIVE`) or in the caption under the figure.
5. **Real UI captures are empty-state.** The dashboard screenshot shows zero responses; no seeded data was fabricated to make it look busier. The builder and mobile survey are real captures from the visual-smoke pipeline.
6. **Living Lattice is honest, therefore sparse.** With 0 stars, 0 forks, 1 contributor and 0 releases, most sockets are empty and one recent burst of commits dominates the skyline (drawn as a 2×2 tower, 4 commits per layer, so it no longer towers over the frame). That is the real state. The "release evolution" chapter says so and fabricates no timeline.
7. **GitHub badge dependency.** The CI badge uses shields.io; it is the only third-party request in the README.
8. **No independent non-Anthropic reviewer.** See [REVIEW_LOG.md](REVIEW_LOG.md): each independent pass used a different Claude model from the one that built that cycle, not a model from another vendor, and it inspected rendered frames and storyboards, not live playback in a browser. Human visual review of playback in the GitHub-rendered page has not been done by a person.
9. **60 fps / long-take playback verification** was not possible in the build environment; frame-by-frame inspection and ffprobe frame counts were used instead.
10. **Stale numbers risk.** The README states a few counts (23 question types, 59 test cases, 9,803-byte respondent bundle). They were verified on the date of this work and will drift if the code changes; `npm run performance:budget` and `QUESTION_TYPES` are the sources to re-check.
11. **Quality gate not met.** Last independent score 71/100 against a 95 target; see the open items at the end of [REVIEW_LOG.md](REVIEW_LOG.md). **Open.**
